# DEC-088: Linguagem e Stack do Worker de Execução

## Decisão

O `worker` é implementado em **Python 3.12**, com **FastAPI** como casca operacional, **[docker-py](https://docker-py.readthedocs.io/)** para falar com o daemon e **[aio-pika](https://aio-pika.readthedocs.io/)** para o RabbitMQ.

## Justificativas

* **Simetria estrutural com o `codegen`.** Os dois componentes têm o mesmo formato — processo consumidor de fila com FastAPI mantido apenas para `/health` e `/metrics` (ARCHITECTURE §3.3). Compartilham a implementação do envelope de log, o registro de métricas Prometheus e as mesmas ferramentas de qualidade (ruff, mypy estrito, pytest). Uma terceira stack no monorepo custaria uma segunda implementação do contrato de observabilidade sem nada em troca.
* **O SDK do Docker em Python é o caminho oficial.** `docker-py` é mantido pela própria Docker e cobre as flags de isolamento exigidas (`network_disabled`, `read_only`, limites de CPU e memória, remoção garantida).
* **A imagem do sandbox já é Python.** O código gerado pelo codegen é obrigatoriamente Python. Manter o worker na mesma linguagem da imagem que ele orquestra reduz a distância entre o que o time depura de um lado e do outro.

## Alternativas consideradas

| Alternativa | Por que não |
| :--- | :--- |
| **Go** | O `prefetch` 1 desta fase (uma execução por vez, uma instância só) elimina justamente o cenário em que a concorrência do Go se pagaria. |
| **Java/Spring Boot** |  Descartada porque o worker não tem nada do que o Spring oferece - sem REST de negócio, sem ORM, sem segurança. |

## Consequências

* O `worker` passa a ter duas dependências de runtime além do esqueleto: `aio-pika` (AMQP) e `docker` (SDK). O `docker-py` não publica o marcador `py.typed`, então o `mypy` estrito recebe um `override` com `ignore_missing_imports` restrito ao módulo `docker.*`.
* O acesso ao daemon do Docker deixa de ser detalhe de implementação e vira **pré-requisito de ambiente**: o socket é montado no container do `worker` e o GID do grupo `docker` do host precisa ser informado em `deploy/.env`. Documentado em [docs/instalacao.md](../instalacao.md) §2.1, com a nota de segurança correspondente.
* Na implementação da T-010, a fila de execução foi declarada com o nome do catálogo de mensagens (ARCHITECTURE §6.3), `executar-codigo`, durável e com `prefetch` 1. O `codegen` deve publicar com esse mesmo nome; nenhum outro serviço declarava filas até aqui, então não há incompatibilidade a tratar.
* O ADR-003 §1.4 deixa de ser a única referência à stack do worker. Se uma implementação futura contrariar esta decisão, é esta DEC que precisa ser revista, não o texto da arquitetura.
